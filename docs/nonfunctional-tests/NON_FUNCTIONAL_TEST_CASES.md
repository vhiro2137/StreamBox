# 非功能性测试用例清单

用例状态以各节和执行记录为准。详细参数在执行前冻结，结果记录到报告和指标 CSV。

## NF-RES 资源与泄漏

### NF-RES-001 状态资源基线（P0，阶段1）

状态：已执行（部分）；完整状态采样受阻。

- 目标：比较空闲、加载、播放、暂停、跳转、切换、停止状态的 CPU/GPU/内存/线程/句柄/网络。
- 环境：固定 Windows 主机、1080p H.264/AAC 本地样本和 HTTPS 直链。
- 步骤：启动并空闲60秒；打开媒体；各状态保持60秒；执行3次跳转和3次切换；停止后观察120秒；重复3轮。
- 采样：1秒；网络记录收发字节率；保存进程计数器、日志和关键界面截图。
- 结果：报告各阶段起始、均值、P95、峰值、结束、净增长。建议基线为停止后资源回落并趋稳；具体允许上限待确认。
- 替代：无GPU计数器时记录任务管理器GPU引擎截图并标明限制。

### NF-RES-002 长时间连续播放（P0，阶段2）

状态：完成（分段累计7202秒）；因中断重启，不宣称严格连续2小时。

- 步骤：30分钟预检无严重异常后，连续循环播放2小时；最终时长待审批；每30分钟执行暂停/继续和跳转。
- 采样：资源每5秒，播放状态/卡顿事件按事件记录；记录温度和系统内存压力（若工具可用）。
- 判定：不得崩溃、死锁或无响应；用线性回归及首尾窗口比较增长率，区分初始化、缓存平台期和持续增长。泄漏阈值待确认。

## NF-STR 压力与控制

### NF-STR-001 媒体压力矩阵（P0，阶段2）

状态：已执行（4K/30fps、720p/60fps）；4K60、专用高码率及超大文件仍受阻。

- 样本：普通1080p；4K；高码率；50/60fps；时长至少2小时或超大文件。编码、码率、帧率、文件大小和SHA-256必须记录。
- 步骤：每个样本冷开3次、连续播放10分钟；4K等压力样本再持续30分钟。
- 指标：打开/首帧时延、CPU/GPU、峰值内存、卡顿次数和累计时长、解码/显示帧、丢帧率、音画偏差。
- 判定：不崩溃；定量阈值待硬件等级和产品目标确认。

### NF-STR-002 高频控制循环（P0，阶段2）

状态：已执行（现有自动化覆盖）；资源增长遥测受阻。

- 步骤：对至少3种媒体执行100循环：播放→暂停→继续→随机跳转→切换→重复加载→停止；动作间隔100–500 ms；三轮。
- 指标：响应时间、失败动作、状态错乱、线程/句柄净增长、崩溃/死锁。
- 建议基线：100循环零崩溃、零永久无响应、最终可停止；资源增长阈值待确认。

## NF-PERF 时延与同步

### NF-PERF-001 关键时延（P0，阶段1）

状态：已执行（部分）；独立窗口可交互、首帧、控制、跳转和切换遥测受阻。

- 测量：进程启动到窗口可交互；打开到媒体就绪；打开到首个可见视频帧/首个音频输出；播放/暂停响应；随机25%、50%、75%跳转；媒体切换。
- 次数：冷启动5次、热启动10次；每个媒体操作10次。
- 输出：最小、最大、中位数、P90；原始时间戳。验收阈值待确认。

### NF-PERF-002 音画同步（P0，阶段2）

- 使用合法的闪光+蜂鸣同步样本；本地、直链、暂停恢复和跳转后各测至少10个同步点。
- 采用外部录制逐帧/音轨分析，报告平均、P95、最大绝对偏差和漂移率。若无采集设备则受阻，不以主观观察代替量化结果。

## NF-NET 网络可靠性

### NF-NET-001 网络矩阵（P0，阶段3）

状态：已执行（仅本机隔离子集）；2 Mbps/300 ms真实播放器探针失败且需用专业整形器复核。

对授权测试服务器执行下列组合；每格3轮、单轮至少5分钟：

| 带宽 | 延迟/抖动 | 丢包 | 断网 |
|---|---|---|---|
| 不限、20、10、5、2 Mbps | 0/0、50/10、150/30、300/50 ms | 0、1%、3%、5% | 5、15、30、60秒 |

- 步骤：播放稳态后施加条件；观察缓冲、暂停/取消、错误；恢复网络并观察自动/手动恢复。
- 指标：加载、首帧、缓冲次数/累计时长、吞吐、超时、恢复时间、错误文案、取消时间。
- 判定：无卡死/崩溃、取消可终止、TLS不关闭；各档性能阈值待确认。
- 受阻：需要隔离代理/网络整形环境和系统变更审批。

## NF-SEC 安全与健壮性

### NF-SEC-001 URL和协议策略（P0，阶段3）

状态：已执行（代码路径核对）；隔离环境中的内网/其他协议动态矩阵受阻/跳过。

- 输入：http、https、本地文件、大小写/空白变体、超长URL、非法字符，以及其他协议。
- 验证：允许/拒绝行为与产品策略一致；错误明确；不执行外部协议或命令。
- 内网、本机、链路本地地址只在隔离环境验证，不访问未经授权目标；协议白名单和SSRF边界需产品确认。

### NF-SEC-002 媒体健壮性（P0，阶段3）

状态：已执行（伪媒体和空文件）；完整异常样本矩阵受阻/跳过。

- 样本：损坏、截断、伪造扩展名、异常时长/分辨率/元数据的合法隔离样本。
- 每样本3轮；监控崩溃、挂起、资源峰值和错误信息。不得生成或使用破坏性载荷。

### NF-SEC-003 TLS、重定向和信息泄露（P0，阶段3）

状态：已执行/失败；TLS证书验证失败，重定向和敏感词初筛已执行，运行时敏感信息仍部分受阻。

- 在授权测试服务验证有效、过期、主机名不匹配和不受信证书；TLS校验不得关闭。
- 验证0、1、多级、循环及跨协议重定向；最大次数待策略确认。
- 检查UI、应用日志、崩溃信息和配置是否暴露Cookie、令牌、完整本地路径或临时媒体地址；证据必须脱敏。
- 受阻：需隔离TLS服务、证书和抓包授权。

## NF-UX 易用性与可访问性

### NF-UX-001 键盘与状态反馈（P1，阶段4）

状态：已执行/失败；18个可聚焦元素中14个无名称，Narrator下完整Tab顺序受焦点抢占影响。

- 从启动开始仅用键盘完成打开、播放、暂停、继续、跳转、音量、列表和全屏；检查Tab顺序、焦点可见、快捷键冲突。
- 检查加载、缓冲、暂停、停止、结束、重试、取消和错误状态；10类异常输入逐项核对文案。
- 在各DPI/分辨率检查裁切、重叠、对比度和触达；屏幕阅读器测试需选定平台工具。
- 通过标准需产品确认，包括目标可访问性规范和键盘覆盖率。

## NF-COMP 兼容性

### NF-COMP-001 显示与音频矩阵（P1，阶段4）

状态：已执行（当前Windows、1920×1080、125%、Realtek默认端点）；其余矩阵受阻/跳过。

- 按环境矩阵逐项执行启动、本地音视频、直链、暂停、跳转、全屏和设备切换。
- 每组合至少一次完整10分钟播放，关键组合3轮；物理音频需人工确认听感并记录设备。
- 缺设备的组合标为受阻，不判通过。

### NF-COMP-002 跨平台（P0，阶段4）

- Windows/Linux/macOS分别执行构建（已有正式方式时）、启动、核心播放、网络、DPI、音频、长稳短测和退出。
- 当前 Linux/macOS 未执行且受阻；需要明确支持版本和带GUI/音频的执行环境。

## NF-REL 发行与生命周期

### NF-REL-001 发行包完整性（P0，阶段5）

状态：已执行（现有便携目录启动和核心文件）；正式包签名、清单和干净VM受阻/跳过。

- 校验包哈希、签名（若适用）、清单、许可证、FFmpeg/Qt运行库和无构建缓存；在干净VM启动。
- 模拟一个依赖缺失场景，确认错误可诊断；不得在当前阶段改包或依赖。

### NF-REL-002 安装升级卸载（P0，阶段5）

状态：受阻/跳过。

- 在可回滚VM执行全新安装、普通用户启动、管理员启动、修复/覆盖安装、上一支持版升级、必要时降级、卸载、重启后残留检查。
- 检查快捷方式、文件关联、用户数据保留策略、安装目录权限和残留文件/注册表项。
- 当前受阻：真实安装卸载、权限和系统变更须单独审批，且需正式发行包及上一版本。

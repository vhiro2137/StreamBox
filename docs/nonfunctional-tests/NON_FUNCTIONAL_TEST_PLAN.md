# StreamBox 独立非功能性测试主计划

## 1. 目标与边界

目标是量化 StreamBox 的资源效率、稳定性、时延、网络恢复、安全、兼容性、易用性和发行质量。本计划只定义测试，不把计划项表述为已通过。

本阶段允许维护 Markdown/CSV 测试资料；禁止修改源码、构建脚本、运行/产品配置和依赖，禁止修复、安装升级工具、系统级网络/证书变更、Git 提交和分支操作。

## 2. 范围与风险

| 范围 | 主要风险 | 优先级 | 阶段 | 当前状态 |
|---|---|---:|---|---|
| CPU/GPU/内存/线程/句柄/网络 | 持续增长、资源耗尽、播放不流畅 | P0 | 1 | 已执行：首轮短时基线；GPU/进程网络和全状态采样受阻 |
| 长时间播放与泄漏 | 缓慢泄漏、句柄或线程累积 | P0 | 2 | 完成：分段累计7202秒，119样本；明确记录非严格连续 |
| 4K/高码率/高帧率/超大文件 | 丢帧、音画失步、OOM | P0 | 2 | 已执行：4K/30fps与720p/60fps；超大/4K60仍受阻 |
| 弱网与恢复 | 卡死、无限重试、错误不清楚 | P0 | 3 | 已执行：本机隔离矩阵；2 Mbps持续播放结果需复核 |
| 高频控制与重复加载 | 竞态、死锁、状态错乱 | P0 | 2 | 已执行：现有自动化100次切换及控制覆盖 |
| 硬件/DPI/多显示器 | 无声、遮挡、缩放错误 | P1 | 4 | 部分受阻：缺设备 |

| 安装/升级/降级/卸载/发行包 | 无法部署、残留或依赖缺失 | P0 | 5 | 受阻：需发行包和系统变更授权 |

## 3. 环境与工具要求

- 基准 Windows 主机：记录 CPU、GPU、内存、磁盘、显示器、DPI、声卡、驱动、Qt、FFmpeg和提交哈希。
- 监控：Windows Performance Recorder/Monitor、任务管理器、Process Explorer 或等价只读工具；网络流量使用系统计数器或授权抓包工具。
- Linux：受支持发行版的物理机或 VM，记录桌面/音频后端和 GPU 驱动。
- macOS：Intel 与 Apple Silicon 至少按产品支持范围选择，记录系统和输出设备。
- 媒体：合法授权、带校验值的普通/4K/高码率/高帧率/长时/损坏样本；不得把临时网络地址作为固定数据。
- 网络：隔离的代理或网络整形环境；TLS 校验始终开启。
- 时间测量：单调时钟；音画同步建议使用带闪光/蜂鸣标记的标准样本和录制分析。

工具缺失时不得安装；登记为受阻并申请批准。

## 4. 阶段与准入/退出

1. 阶段1—环境冻结与基线：确认版本、空闲资源、启动/加载/首帧基础数据。退出条件：环境记录完整，每场景至少3次原始数据。
2. 阶段2—本地压力与长稳：资源趋势、压力媒体、高频控制。退出条件：原始采样和异常日志齐全，趋势完成分类。
3. 阶段3—网络与安全：网络矩阵、TLS、重定向、异常输入、敏感信息检查。退出条件：所有授权场景有结论，未授权项标为受阻。
4. 阶段4—兼容性与可用性：硬件、DPI、多屏、跨平台、键盘与反馈。退出条件：矩阵逐格标记，缺失环境不得判通过。
5. 阶段5—发行验证：全新安装、升级、降级、卸载和包完整性。退出条件：系统变更获批且证据可回滚。

## 5. 通用执行规则

- 冷启动和热启动分开；各时延场景建议至少5次，报告中位数、P90、最小和最大值。
- 资源采样建议间隔1秒；快速时延事件建议使用不低于10 Hz事件记录或代码已有日志时间戳。
- 长稳建议先30分钟预检，再2小时基线，最终持续时长待审批；记录开始、峰值、结束、净增长和每小时增长率。
- 高频控制建议先100循环，再根据结果决定是否扩展至1000循环；每次动作间隔建议100–500 ms，具体值记录在执行记录中。
- 每次执行记录样本校验值、网络条件、版本、开始/结束时间、退出码和异常。
- 将一次性初始化、达到平台上限的正常缓存和持续近似线性增长分别标记；未经证据不得称为泄漏。

## 6. 指标与验收阈值

项目目前未形成完整的性能 SLO，以下均为建议基线，不是既定通过标准：

| 指标 | 建议基线用途 | 待确认验收阈值 |
|---|---|---|
| 启动、加载、首帧、跳转、切换 | 在固定主机/样本上建立中位数和P90，后续版本回归比较 | 绝对时长与允许回归百分比 |
| CPU/GPU/内存 | 记录稳定播放阶段均值、P95、峰值 | 各分辨率/编码允许上限 |
| 线程/句柄 | 稳态应进入平台期；循环结束接近预热后基线 | 允许净增长和增长率 |
| 卡顿/丢帧/音画同步 | 以标准样本和固定硬件建立观测基线 | 允许次数、累计时长、丢帧率和同步偏差 |
| 网络恢复 | 按网络矩阵记录缓冲、错误和恢复时间 | 每档网络的恢复/失败时限 |

建议依据是可重复的同机同样本测量和用户体验关键路径，而非虚构行业阈值。正式判定前需产品负责人确认阈值。

## 7. 证据与结果管理

- 原始数据使用 `METRICS_COLLECTION_TEMPLATE.csv` 的副本，禁止覆盖模板。
- 截图、性能追踪和日志按 `日期_提交_用例_轮次` 命名，并记录 SHA-256。
- 状态只允许：计划、已执行、未执行、受阻、完成。
- 测试发现只登记，不在本阶段实施修复。

## 8. 退出与停止条件

出现崩溃、系统不稳定、温度/资源异常、样本越权、敏感信息暴露或测试可能影响非授权目标时立即停止。涉及安装卸载、证书、网络配置、权限用户或安全隔离环境的操作必须另行审批。
